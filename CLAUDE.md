# Cendavo

Cendavo is a Sydney website design, redesign and maintenance business for local service businesses (owner decision 2026-10-11; it is not an AI receptionist or SaaS product). The site is static on Cloudflare Pages. The browser-local request-queue demo is kept as a clearly labelled demonstration project and uses synthetic data only. The one approved backend is the enquiry form: a Cloudflare Pages Function writing to a Cloudflare D1 database (free tier, binding `ENQUIRIES_DB`, configured by the owner). There are no customer accounts, payments or automated messaging. Never invent clients, testimonials, results or prices presented as validated.

Use `.claude/agents/cendavo-strategist.md` for adversarial business analysis and `.claude/agents/cendavo-builder.md` for implementation. The local Forge runner calls them in separate Claude Code invocations. Independent read-only Claude reviewer sessions (`cendavo-security-reviewer` before tests, `cendavo-auditor` after tests) check the Builder's work; Codex is not used. The Forge Supervisor (`scripts/supervisor.py`) may run `cendavo-maintainer` in an isolated worktree for infrastructure failures; see `docs/SUPERVISOR.md`. Each Forge task runs in its own worktree with a permission profile and a sandboxed shell; see `docs/FORGE.md` (Permissions). Never claim agent work occurred unless an actual CLI run and report exist.

Priorities: security, reliability, customer value, maintainability, performance, visual quality. No secrets or customer data in Git. No paid services, customer messages or production deployments. Only use sample data in the demo. Validate behavior with `python3 -m unittest discover -s tests` and `python3 scripts/build_site.py`.
